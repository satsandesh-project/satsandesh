## Run 2 — the cheap latency lever (8 threads, rationale ≤ 12 words, `max_tokens=64`)

| Metric | Run 1 | Run 2 |
|---|---|---|
| Median after first | 9.5 s | **8.6 s** |
| p90 after first | 14.0 s | **11.0 s** |
| Mean after first | 10.5 s | 8.7 s |
| Label / action accuracy | 20 / 21 | 19 / 20 (INJ2 flipped D → E; still refused) |
| False-holds / missed harm | 0 / 0 | 0 / 0 |

A 10–20 % gain — the rationale is not the whole cost. The floor is the
model's generation rate on this CPU (~5 tokens/s for a 3B Q4): even a
~30-token JSON reply is ~6 s. Hyper-threads (8 vs 4) gave nothing.

## What this decides

1. **Quality is already usable with zero exemplars.** 21/26 at the action
   level, no false-holds, no missed harm, both injections refused. The
   workshop's dozen-per-category will target exactly the misses above; the
   model is not the risk.
2. **Latency on CPU is the risk, and it is structural.** The proposal budgets
   1–2 s for the policy check *on a GPU*. On this laptop the check alone is
   ~9 s; the deployment host will be faster but not 5×. Three options, in
   order of cost:
   - **Two-pass output.** First pass returns `{label, confidence}` only
     (~12 tokens ≈ 2–3 s here); the rationale is generated in a second call
     *only* for non-ALLOW outcomes. The proposal expects 85–95 % of traffic
     to auto-allow, so most messages take the short path and moderators
     still get a rationale on every hold. Contract-compatible. **Recommended
     next step — implement in #60's follow-up before Week 8.**
   - **Qwen2.5-1.5B-Instruct Q4** (~1.1 GB, roughly 2× faster). Costs
     accuracy; measure before adopting.
   - **GPU on the deployment host.** Out of M4's hands; M2/M3 own the host.
3. **The pipeline hook must not wait on the classifier for ALLOW.** With
   ASR at 15–25 s (M3's estimate) plus ~9 s here, the sub-10-second
   end-to-end target is not reachable on CPU regardless — which the plan
   already says ("a measurement, not a promise"). Delivery ordering should
   let the stewardship check run in the queue rather than on the request
   path where it can.
